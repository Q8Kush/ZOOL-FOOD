# ZOOL FOOD

منصة توصيل عربية باتجاه RTL تجمع المطاعم والصيدليات والسوبرماركت في تجربة واحدة.

## التقنية
- Next.js 14 App Router + React 18 + TypeScript
- Supabase Auth + PostgreSQL + Row Level Security
- Vercel للاستضافة والنشر
- واجهة عربية متجاوبة للهواتف وسطح المكتب

## التشغيل المحلي
1. استخدم Node.js 20 أو أحدث.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env.local` وأضف مفاتيح Supabase العامة.
4. شغّل `npm run dev`.

## ما تم بناؤه
### تجربة العميل
- استعراض المتاجر المعتمدة حسب النشاط.
- عرض كتالوج المنتجات المتاحة.
- سلة تمنع جمع منتجات من متاجر مختلفة.
- إنشاء حساب وتسجيل الدخول عبر Supabase Auth.
- حفظ عناوين التوصيل وإعادة استخدامها.
- إتمام الطلب عبر RPC آمن من قاعدة البيانات.
- الدفع عند الاستلام فقط، مع احتساب رسوم التوصيل وضريبة القيمة المضافة على الخادم.
- عرض سجل الطلبات وإلغاء الطلب قبل قبوله من المتجر.

### بوابة التاجر `/portal/merchant`
- عرض الطلبات وتحديثها ضمن مراحل العمل المسموحة.
- إضافة المنتجات وتحديث توفرها وحذفها.
- إدارة كتالوج المتجر.

### بوابة المندوب `/portal/courier`
- تفعيل/إيقاف استقبال الطلبات.
- عرض الطلبات الجاهزة وقبول مهمة توصيل ذرياً عبر RPC.
- تحديث مراحل الاستلام والتوصيل.

### لوحة الإدارة `/portal/admin`
- مؤشرات المتاجر والطلبات والحسابات.
- اعتماد المتاجر أو إيقاف اعتمادها.
- إنشاء متجر وربطه بحساب مسجل وتحويل الحساب إلى تاجر عبر RPC محمي.
- إدارة أدوار العملاء والتجار والمناديب.
- مراجعة الطلبات والحسابات.

### قاعدة البيانات والأمان
- جداول الملفات الشخصية والعناوين والمتاجر والمنتجات والطلبات والتوصيلات والمراجعات والإشعارات وغيرها.
- سياسات RLS مفعّلة على جداول التطبيق.
- تسعير الطلب والضريبة وفحص المخزون والتحقق من المنتجات يتم على الخادم داخل `place_order`.
- انتقالات حالات الطلب ومهام التوصيل محمية عبر RPC.
- إضافة دوال إدارية محمية لإنشاء المتاجر وإدارة الأدوار.
- لا يوجد مفتاح service-role في الواجهة أو المستودع.

## فحوصات المشروع
- `npm run typecheck`
- `npm run build`
- GitHub Actions يشغّل الفحصين عند كل تحديث على `main`.

## ما يلزم قبل استقبال طلبات حقيقية
- تسجيل حساب إدارة أولي، ثم إنشاء حسابات التجار والمناديب وربطها من لوحة الإدارة.
- ضم متاجر حقيقية وإدخال منتجات وأسعار ومخزون وصور صحيحة.
- اختبار دورة الطلب كاملة بحسابات منفصلة للعميل والتاجر والمندوب والإدارة.
- تفعيل نطاق التوصيل وسياسات الإلغاء والاسترجاع ودعم العملاء.
- دمج بوابة دفع سعودية عند الرغبة في الدفع الإلكتروني، مع webhooks موقعة.
- دمج الخرائط وتحديد الموقع وتتبع المندوب والإشعارات والرسائل النصية.
- بناء مسار الوصفات الطبية ومراجعة الصيدلي والحصول على الموافقات التنظيمية اللازمة قبل بيع المنتجات المقيدة.
- إعداد سياسات الخصوصية والشروط والضرائب والامتثال التشغيلي.

**مهم:** قاعدة البيانات الحالية تبدأ دون متاجر أو منتجات؛ لذلك لن تظهر متاجر حقيقية للعميل حتى يضيفها المسؤول من لوحة الإدارة. لا تستخدم بيانات العرض التجريبي لاستقبال طلبات حقيقية.
